# 测试环境连接配置速查

> **用途**：手工测试期间用数据库工具（DBeaver / Navicat / DataGrip / MySQL Workbench）连接查数据，或用浏览器/Postman 直接调 API 时的一站式速查。
> **适用版本**：v0.1.0（本地开发 / 便携标准包生产环境同源）
> **文档日期**：2026-07-26

## 二、MySQL 数据源（两个库都在同一实例）

**JDBC 连接串**（DBeaver / Navicat 等图形化工具可直接粘贴）：

| 库名 | JDBC URL | 用户 | 密码 |
|------|----------|------|------|
| **配置库**（模板/接口/连接/审计以外的一切） | `jdbc:mysql://localhost:3306/powergateway_config?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8` | `root` | `qwe12345` |
| **审计库**（`sql_audit_log` 单表） | `jdbc:mysql://localhost:3306/powergateway_audit?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8` | `root` | `qwe12345` |

**图形化工具最简填法**：
- Host: `localhost` · Port: `3306` · User: `root` · Password: `qwe12345`
- 建两个连接分别指向 `powergateway_config` 与 `powergateway_audit`

**驱动版本**：MySQL 5.7+ / 8.0+ 均可（后端用 `mysql-connector-j` 通过 `com.mysql.cj.jdbc.Driver`）

## 三、配置库表清单（`powergateway_config`）

| 类别 | 表名 | 用途 | 手工测试常查 |
|------|------|------|:---:|
| 用户 / 权限 | `sys_user` | 用户 + BCrypt 密码 | ✅ |
| 系统配置 | `sys_config` | KV 配置（缓存 TTL、审计留存天数、日志菜单开关等） | ✅ |
| 操作日志 | `sys_log` / `sys_log_history` | 后台操作日志 + 归档 | ✅ |
| 转换配置 | `convert_template` | 报文转换模板（含 `mapping_rule` JSON） | ✅ |
| 转换配置 | `channel_config` | 渠道配置（识别字段 → 关联模板） | ✅ |
| 转换配置 | `port_route` | 端口分发路由（B 系统地址 + 双向模板） | ✅ |
| 接口开发 | `db_connection` | 业务库连接（密码 AES 加密） | ✅ |
| 接口开发 | `interface_config` | 接口配置（`config_json` + `status` + `path`） | ✅ |
| 接口开发 | `shard_config` | 分库分表规则 | 中 |
| 接口开发 | `field_formula` | 常用字段公式（CR-001 落地后会加 `dict_mapping`） | 中 |
| 缓存/监控 | `perf_stat` / `perf_alert` | 性能统计 + 告警记录 | ✅ |

**审计库表清单（`powergateway_audit`）**：
- `sql_audit_log` — SQL 审计日志（增/删/改都在这查 beforeSnapshot / afterSnapshot）

## 四、常用校验 SQL（复制即用）

### 4.1 用户与登录
```sql
-- 看 admin 是否存在、密码是否 BCrypt（$2a$ 开头）
SELECT id, username, role, LENGTH(password) AS pwd_len, LEFT(password, 4) AS pwd_prefix, deleted
FROM powergateway_config.sys_user
WHERE username = 'admin';

-- 三角色都在
SELECT role, COUNT(*) FROM powergateway_config.sys_user WHERE deleted = 0 GROUP BY role;
```

### 4.2 转换配置
```sql
-- 最近保存的模板
SELECT id, name, src_format, target_format, is_latest, is_deleted, create_time
FROM powergateway_config.convert_template
ORDER BY id DESC LIMIT 10;

-- 模板的完整 JSON（映射规则 + 加工规则）
SELECT name, mapping_rules, process_rules
FROM powergateway_config.convert_template
WHERE id = ?;

-- 渠道与端口路由
SELECT * FROM powergateway_config.channel_config ORDER BY id DESC LIMIT 10;
SELECT * FROM powergateway_config.port_route ORDER BY id DESC LIMIT 10;
```

### 4.3 接口配置
```sql
-- 接口列表 + 状态 + 缓存开关
SELECT id, name, path, op_type, status, cache_enabled, cache_ttl_seconds, shard_config_id
FROM powergateway_config.interface_config
ORDER BY id DESC LIMIT 20;

-- 某个接口的完整配置 JSON
SELECT id, name, config_json
FROM powergateway_config.interface_config
WHERE id = ?;

-- 数据库连接（密码应为 AES 密文，非明文）
SELECT id, name, db_type, url, LEFT(password, 8) AS pwd_prefix, LENGTH(password) AS pwd_len
FROM powergateway_config.db_connection;
```

### 4.4 日志与审计
```sql
-- 最近后台操作日志
SELECT id, username, module, op_type, target_id, status, cost_ms, op_time
FROM powergateway_config.sys_log
ORDER BY id DESC LIMIT 20;

-- 最近 SQL 审计（审计库！）
SELECT id, interface_id, op_type, status, sql_text, before_snapshot, after_snapshot, cost_ms, op_time
FROM powergateway_audit.sql_audit_log
ORDER BY id DESC LIMIT 20;

-- 最近性能统计
SELECT id, interface_id, op_type, success, cost_ms, op_time
FROM powergateway_config.perf_stat
ORDER BY id DESC LIMIT 20;
```

### 4.5 系统配置（sys_config）
```sql
-- 全部 KV
SELECT config_key, config_value, description FROM powergateway_config.sys_config;

-- 常见 KV（v0.1.0 预置）
-- cache.query.ttl = 300
-- cache.template.ttl = 600
-- audit.log.retention.days = 365
-- log.menu.enabled = true
```

## 五、Redis（可选）

- **地址**：`localhost:6379`（无密码，无 DB 索引区分）
- **常见 key 前缀**：
  - `pg:template:*` — 转换模板缓存
  - `pg:meta:db:*` — 表结构元数据缓存（TTL 24h）
  - `pg:query:*` — 接口查询结果缓存（M2-10 双层缓存）
  - `pg:satoken:*` — 会话 token（Sa-Token 存 Redis）
- **推荐工具**：Redis Insight 或 `redis-cli`
- **`FLUSHDB` 前请确认没有其他项目共用 6379**

## 六、pg-testkit（测试工具）API 快查

`pg-testkit` 运行在 8081，通过 HTTP + JDBC 直连的方式与主后端 8080 协作，**不引用 backend 内部类**。

**默认接口清单**（无需登录，`localhost:8081` 前缀）：

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/test/health` | 健康检查 |
| POST | `/test/mock-server/start` | 启动 9999 端口的 Mock B 系统 |
| POST | `/test/mock-server/stop` | 停止 Mock |
| POST | `/test/mock-server/configure` | 配置 Mock 响应规则（JSON body） |
| GET | `/test/mock-server/requests` | 查询 Mock 收到的请求历史 |
| POST | `/test/mock-server/verify` | 验证请求是否符合预期 |
| POST | `/test/db/query` | 直连 MySQL 跑校验 SQL |
| POST | `/test/run-scenario` | 执行预设测试场景 JSON |
| GET | `/test/results` | 拉取测试结果报告 |

> ⚠️ **v0.1.0 已交付的仅是 pg-testkit 的骨架**（`MockServerService` / `TestDataFactory` / `TestScenarioRunner` / `TestApiController` / `PgAssertions`）。**Faker 10 万条数据 + 完整 10 表 DDL + Mock 规则持久化** 归入 v0.2.0（见 [路线图 · v0.2.0](../06-项目管理/路线图.md#v020--test-1-完善--sqlite-分支--fn-12-字典映射预估-2--3-周)），当前手工测试**不必依赖 pg-testkit** — 直接管理台点击 + MySQL 客户端查表即可覆盖 v0.1.0 全部场景。

## 七、启动顺序（手工测试前置）

```bash
# 1. 确认外部依赖已启动
mysql -u root -pqwe12345 -e "SHOW DATABASES LIKE 'powergateway_%';"
redis-cli ping   # 应返回 PONG

# 2. 启动后端（终端 A）
cd backend
mvn spring-boot:run
# 等到看到 "Started PowergatewayApplication in X seconds"，Ctrl+C 结束

# 3. 启动前端（终端 B）
cd frontend
npm install     # 首次运行需要
npm run dev
# 看到 "Local: http://localhost:5173/"

# 4. （可选）启动测试工具（终端 C）
cd pg-testkit
mvn spring-boot:run
# 端口 8081
```

**端口占用排查**（Windows PowerShell）：
```powershell
netstat -ano | findstr ":8080 :5173 :6379 :3306 :8081 :9999"
# 拿到 PID 后：taskkill /F /PID <pid>
```

## 八、常见陷阱

| 症状 | 排查 |
|------|------|
| 前端登录 401 | 后端未启动 / MySQL 未启 / `sys_user` 无 admin 账户 |
| Swagger 打开空白 | `springdoc.swagger-ui.path` 被改；确认访问 `/swagger-ui.html` 而非 `/swagger-ui/index.html` |
| 修改数据后前端不刷新 | Redis 有缓存；`DEL pg:query:*` 或点前端"清除缓存"按钮 |
| 审计日志表 `sql_audit_log` 查不到 | 数据在**审计库** `powergateway_audit`，别在配置库找 |
| Mock 9999 端口 EADDRINUSE | 上一次没 `/test/mock-server/stop` 就退了，重启 pg-testkit 或杀 9999 端口 |
