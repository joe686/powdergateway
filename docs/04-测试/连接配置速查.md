# 测试环境连接配置速查

> **用途**：手工测试期间用数据库工具（DBeaver / Navicat / DataGrip / MySQL Workbench）连接查数据，或用浏览器/Postman 直接调 API 时的一站式速查。
> **适用版本**：v0.2.x（本地开发 / 便携标准包生产环境同源）
> **文档日期**：2026-07-28

---

## 三·B、样例业务库 `pg_demo`（DemoDb · 接口开发练手）

**用途**：给 PG 的"接口开发"功能提供一个**独立的、可随意增删改查的业务库**，不污染 `powergateway_config`。由 pg-testkit（8081）通过 `POST /testkit/demo-db/init` 一键建表灌种子。

**首次启用步骤**（若 MySQL 里无 `pg_demo` 库）：

```bash
# 1. 建库（一次即可）
mysql -u root -pqwe12345 -e "CREATE DATABASE IF NOT EXISTS pg_demo DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2. 确认 pg-testkit/src/main/resources/application.yml 里 pg-testkit.db 下已配：
#    demo-url:      jdbc:mysql://localhost:3306/pg_demo?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
#    demo-user:     root
#    demo-password: qwe12345
# （2026-07-28 已配好，无需再改）

# 3. 启动 pg-testkit 后调 init（幂等）
curl -X POST http://localhost:8081/testkit/demo-db/init
```

**10 张表清单**（v0.2.5 起 · CR-005 已把 7 张占位表补真 DDL + 种子）：

| 表名 | 种子行数 | 关键字段 / 说明 |
|------|:---:|------|
| `demo_user` | 5 | id / user_no / name / gender / phone / balance / status / created_at · 张三 / 李四 / 王五 / 赵六 / 钱七 |
| `demo_account` | 6 | id / user_id / account_no / balance · 张三 2 账户 · 其他各 1 |
| `demo_txn` | 8 | id / user_id / amount / txn_time · 交易流水（v1.1 加 account_id 等 + Faker 10 万条）|
| `demo_product` | 10 | product_code / name / category_code / price / stock · iPhone/MacBook/AirPods/Kindle/Java/设计模式/算法/巧克力/牛肉干/茶叶 |
| `demo_order` | 7 | order_no / user_id / total_amount / status(CREATED/PAID/SHIPPED/DONE/CANCELED) |
| `demo_order_item` | 10 | order_id / product_id / qty / unit_price / subtotal · 10 明细分布 7 单 |
| `demo_address` | 4 | user_id / receiver / phone / province+city+district+detail / is_default · 张三 2 地址（默认深圳）· 李/王 各默认地址 · 赵/钱无 |
| `demo_dict` | 8 | dict_type / dict_code / dict_name · product_category(3) + order_status(5) |
| `demo_config` | 3 | config_key / config_value(TEXT) · site.name / promotion.banner / feature.flags 三条 JSON |
| `demo_log` | 15 | user_id / action / target / detail / log_time · 登录/下单/支付/取消/登出/改地址混合日志 |

**关键关联**：
- `demo_user.id` ← account/txn/address/order/log 各 .user_id
- `demo_order.id` ← order_item.order_id
- `demo_product.id` ← order_item.product_id
- `demo_dict.dict_code` ← product.category_code（dict_type='product_category'）· order.status（dict_type='order_status'）

> 更详细的字段含义、关联图、连表 CRUD 场景 SQL 见 [`pg_demo接口开发练习.md`](./pg_demo接口开发练习.md)。
> v1.1 还会给 `demo_txn` 补 Faker 10 万条用于分库分表压测（当前 seed 只够功能演示）。

**在 PG 管理台把 `pg_demo` 添加为业务数据源**（做完就能在接口向导里选到它）：

1. 登录 http://localhost:5173（`admin` / `Admin@123`）
2. 进 **系统管理 → 数据源管理 → 新建**
3. 填：名称 `pg_demo（DemoDb）` · 类型 `MySQL` · URL 见上表 · 用户 `root` · 密码 `qwe12345`
4. 测试连接通过后保存（PG 会自动 AES 加密密码写 `powergateway_config.db_connection`）

**样例数据校验 SQL**：

```sql
-- 看 demo_user 种子
SELECT * FROM pg_demo.demo_user;
-- 预期：U000001 张三 / U000002 李四

-- 各表行数（等同 /testkit/demo-db/stats）
SELECT
  (SELECT COUNT(*) FROM pg_demo.demo_user)       AS demo_user,
  (SELECT COUNT(*) FROM pg_demo.demo_account)    AS demo_account,
  (SELECT COUNT(*) FROM pg_demo.demo_txn)        AS demo_txn;
```

**重置 / DROP**：

```bash
# TRUNCATE 全部 demo_* 表后重灌张三李四
curl -X POST http://localhost:8081/testkit/demo-db/reset

# DROP 全部表（危险，之后要重新 init）
curl -X POST http://localhost:8081/testkit/demo-db/drop
```

## 四、常用校验 SQL（复制即用）

### 4.1 用户与登录
```sql
-- 看 admin 是否存在、密码是否 BCrypt（$2a$ 开头）
SELECT id, username, role, LENGTH(password) AS pwd_len, LEFT(password, 4) AS pwd_prefix, deleted
FROM powergateway_config.sys_user
WHERE username = 'admin';

-- 三角色都在
SELECT role, COUNT(*) FROM powergateway_config.sys_user WHERE deleted = 0 GROUP BY role;
```

### 4.2 转换配置
```sql
-- 最近保存的模板
SELECT id, name, src_format, target_format, is_latest, is_deleted, create_time
FROM powergateway_config.convert_template
ORDER BY id DESC LIMIT 10;

-- 模板的完整 JSON（映射规则 + 加工规则）
SELECT name, mapping_rules, process_rules
FROM powergateway_config.convert_template
WHERE id = ?;

-- 渠道与端口路由
SELECT * FROM powergateway_config.channel_config ORDER BY id DESC LIMIT 10;
SELECT * FROM powergateway_config.port_route ORDER BY id DESC LIMIT 10;
```

### 4.3 接口配置
```sql
-- 接口列表 + 状态 + 缓存开关
SELECT id, name, path, op_type, status, cache_enabled, cache_ttl_seconds, shard_config_id
FROM powergateway_config.interface_config
ORDER BY id DESC LIMIT 20;

-- 某个接口的完整配置 JSON
SELECT id, name, config_json
FROM powergateway_config.interface_config
WHERE id = ?;

-- 数据库连接（密码应为 AES 密文，非明文）
SELECT id, name, db_type, url, LEFT(password, 8) AS pwd_prefix, LENGTH(password) AS pwd_len
FROM powergateway_config.db_connection;
```

### 4.4 日志与审计
```sql
-- 最近后台操作日志
SELECT id, username, module, op_type, target_id, status, cost_ms, op_time
FROM powergateway_config.sys_log
ORDER BY id DESC LIMIT 20;

-- 最近 SQL 审计（FB-043 后与配置库同库）
SELECT id, interface_id, op_type, status, sql_text, before_snapshot, after_snapshot, cost_ms, op_time
FROM powergateway_config.sql_audit_log
ORDER BY id DESC LIMIT 20;

-- 最近性能统计
SELECT id, interface_id, op_type, success, cost_ms, op_time
FROM powergateway_config.perf_stat
ORDER BY id DESC LIMIT 20;
```

### 4.5 系统配置（sys_config）
```sql
-- 全部 KV
SELECT config_key, config_value, description FROM powergateway_config.sys_config;

-- 常见 KV（v0.1.0 预置）
-- cache.query.ttl = 300
-- cache.template.ttl = 600
-- audit.log.retention.days = 365
-- log.menu.enabled = true
```

## 五、Redis（可选）

- **地址**：`localhost:6379`（无密码，无 DB 索引区分）
- **常见 key 前缀**：
  - `pg:template:*` — 转换模板缓存
  - `pg:meta:db:*` — 表结构元数据缓存（TTL 24h）
  - `pg:query:*` — 接口查询结果缓存（M2-10 双层缓存）
  - `pg:satoken:*` — 会话 token（Sa-Token 存 Redis）
- **推荐工具**：Redis Insight 或 `redis-cli`
- **`FLUSHDB` 前请确认没有其他项目共用 6379**

## 六、pg-testkit（测试工具）API 快查

`pg-testkit` 运行在 8081，通过 HTTP + JDBC 直连的方式与主后端 8080 协作，**不引用 backend 内部类**。

**默认接口清单**（无需登录，`localhost:8081` 前缀）：

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/test/health` | 健康检查 |
| POST | `/test/mock-server/start` | 启动 9999 端口的 Mock B 系统 |
| POST | `/test/mock-server/stop` | 停止 Mock |
| POST | `/test/mock-server/configure` | 配置 Mock 响应规则（JSON body） |
| GET | `/test/mock-server/requests` | 查询 Mock 收到的请求历史 |
| POST | `/test/mock-server/verify` | 验证请求是否符合预期 |
| POST | `/test/db/query` | 直连 MySQL 跑校验 SQL |
| POST | `/test/run-scenario` | 执行预设测试场景 JSON |
| GET | `/test/results` | 拉取测试结果报告 |
| **POST** | **`/testkit/demo-db/init` `[?force=true]`** | **初始化样例业务库 `pg_demo`（幂等；见 §三·B）** |
| **POST** | **`/testkit/demo-db/reset`** | **TRUNCATE 全部 demo_* 表后重灌种子** |
| **POST** | **`/testkit/demo-db/drop`** | **DROP 全部 demo_* 表（危险）** |
| **GET** | **`/testkit/demo-db/stats`** | **各 demo_* 表行数统计** |

> ⚠️ **v0.1.0 已交付的仅是 pg-testkit 的骨架**（`MockServerService` / `TestDataFactory` / `TestScenarioRunner` / `TestApiController` / `PgAssertions` / `DemoDbController` + `MysqlDemoDbInitializer`）。**Faker 10 万条数据 + 完整 10 表 DDL + Mock 规则持久化** 归入 v1.1（详见 §三·B）。**v0.2.x 起 DemoDb（`pg_demo`）已可用**，接口开发手工测试推荐用它做业务库。

## 七、启动顺序（手工测试前置）

```bash
# 1. 确认外部依赖已启动
mysql -u root -pqwe12345 -e "SHOW DATABASES LIKE 'powergateway_%';"
redis-cli ping   # 应返回 PONG

# 2. 启动后端（终端 A）
cd backend
mvn spring-boot:run
# 等到看到 "Started PowergatewayApplication in X seconds"，Ctrl+C 结束

# 3. 启动前端（终端 B）
cd frontend
npm install     # 首次运行需要
npm run dev
# 看到 "Local: http://localhost:5173/"

# 4. （可选）启动测试工具（终端 C）
cd pg-testkit
mvn spring-boot:run
# 端口 8081
```

**端口占用排查**（Windows PowerShell）：
```powershell
netstat -ano | findstr ":8080 :5173 :6379 :3306 :8081 :9999"
# 拿到 PID 后：taskkill /F /PID <pid>
```

## 八、常见陷阱

| 症状 | 排查 |
|------|------|
| 前端登录 401 | 后端未启动 / MySQL 未启 / `sys_user` 无 admin 账户 |
| Swagger 打开空白 | `springdoc.swagger-ui.path` 被改；确认访问 `/swagger-ui.html` 而非 `/swagger-ui/index.html` |
| 修改数据后前端不刷新 | Redis 有缓存；`DEL pg:query:*` 或点前端"清除缓存"按钮 |
| 审计日志表 `sql_audit_log` 查不到 | FB-043 后已合并到 `powergateway_config` 库，直接在 config 库查（v0.1.x 老库客户跑 `db/migration-audit-to-config.sql`）|
| Mock 9999 端口 EADDRINUSE | 上一次没 `/test/mock-server/stop` 就退了，重启 pg-testkit 或杀 9999 端口 |
