## 零、使用说明

### 0.1 优先级分档

| 档位 | 含义 | 建议执行时机 |
|------|------|-------------|
| **P0 冒烟** | 不通过则整个系统不可用，10 条以内 | 每次拉代码 / 打 tag 前必跑 |

### 0.2 用例编号

`MT-<组号>-<序号>` — 例：`MT-01-03` 是第 1 组第 3 条。**组号与本文档章节号一致**，便于快速定位。

### 0.3 结果记录格式

在每次执行时，建议在本地建一份 `docs/04-测试/execution/YYYY-MM-DD-手工测试记录.md`，按下表格式勾记：

## 一、环境自检与登录（P0 冒烟）

### MT-01-01 【P0】后端健康检查

- **前置**：后端已启
- **步骤**：浏览器打开 `http://localhost:8080/api/health`
- **预期**：返回 `{"code":200,"message":"success","data":"ok"}` 或类似 200 响应
- **DB 校验**：无

### MT-01-02 【P0】Swagger 可打开

- **步骤**：访问 `http://localhost:8080/swagger-ui.html`
- **预期**：Swagger UI 加载完成，能看到 `auth`、`template`、`interface`、`exec`、`convert`、`dispatch`、`home` 等分组
- **DB 校验**：无

### MT-01-03 【P0】admin 账号存在且密码为 BCrypt

- **步骤**：MySQL 客户端连 `powergateway_config`，执行：
  ```sql
  SELECT id, username, role, LEFT(password, 4) AS pwd_prefix, deleted
  FROM sys_user WHERE username = 'admin';
  ```
- **预期**：1 条记录，`pwd_prefix` 为 `$2a$`，`role='admin'`，`deleted=0`

### MT-01-04 【P0】使用 admin 登录成功

- **步骤**：`http://localhost:5173/login`，用户名 `admin`，密码 `Admin@123`，点登录
- **预期**：
  1. 页面跳到 `/dashboard`（首页）
  2. 顶部右上角显示 `admin` 用户名
  3. 左侧侧边栏加载出菜单树（首页 / 接口开发 / 转换配置 / 辅助工具 / 系统管理…）
- **DB 校验**：`SELECT * FROM sys_log WHERE op_type='LOGIN' ORDER BY id DESC LIMIT 1;` 应有本次登录记录

### MT-01-05 【P0】F5 刷新后仍处于登录态

- **前置**：MT-01-04 已登录
- **步骤**：F5 刷新首页
- **预期**：仍在 `/dashboard`，不跳回登录页，侧边栏菜单正常渲染

## 二、登录 / 权限 / 回归（FB-037 / FB-038）

### MT-02-01 【P0 · FB-037 回归】未登录访问后台自动跳登录

- **前置**：浏览器 F12 → Application → Cookies → 清空 `satoken`；LocalStorage 清空
- **步骤**：地址栏直接输 `http://localhost:5173/dashboard`
- **预期**：**立即跳转到 `/login`**，不能看到任何 dashboard 内容闪现

### MT-02-02 【P1 · FB-037 回归】后端返回业务码 401 也应清 store 并跳登录

- **前置**：已登录状态。用 MySQL 手动使 satoken 失效（可以直接 `DELETE FROM sys_user WHERE username='admin'` 再插回 —— 或最简：等 token 超时；或前端手工改本地 satoken 值为无效串）
- **步骤**：在管理台点任意菜单触发 API 调用
- **预期**：
  1. 弹出登录失效提示或直接跳回 `/login`
  2. store 内 user 信息被清空（F12 看 Pinia）
  3. localStorage 中的 `satoken` 键被移除

### MT-02-03 【P1 · FB-038 回归】登录页毛玻璃视觉

- **步骤**：清 cookie → 打开 `/login`
- **预期**：
  1. 背景不是纯白/纯黑，采用**渐变或图片 + 卡片毛玻璃 (`backdrop-filter: blur`)**
  2. 登录卡片有圆角 + 阴影，标题/输入框对齐美观
  3. 切换主题（如有）后卡片颜色对应变化，无 tokens undefined 报错

### MT-02-04 【P1】非 admin 角色菜单收窄

- **前置**：先用 admin 登录，进 `系统管理 → 用户管理`，新建 `testuser1 / Test@123` 角色为 `user`；新建 `testreader / Test@123` 角色为 `readonly`
- **步骤**：退出 → 用 `testuser1` 登录 → 查看侧边栏
- **预期**：
  - `user` 看不到"用户管理 / 系统配置 / 分库分表"这类敏感菜单
  - 试图地址栏直接访问 `/system/user` 被路由守卫拦截
- **DB 校验**：`SELECT * FROM sys_user WHERE username IN ('testuser1','testreader');` 密码为 BCrypt 密文

### MT-02-05 【P2】readonly 角色执行删除被拒

- **前置**：MT-02-04 已建 `testreader`
- **步骤**：用 `testreader` 登录 → 进任意有删除按钮的列表 → 点删除
- **预期**：前端按钮 disabled 或点击后返回 403 提示无权限

### MT-02-06 【P2】自删末位 admin 保护

- **前置**：确保 `sys_user` 中 `admin` 角色只剩当前登录这一个
- **步骤**：用 admin 登录 → 用户管理 → 尝试删除自己
- **预期**：后端返回业务错误：`不能删除自己 / 系统必须保留至少一个 admin`

## 四、报文转换配置向导（UX-D + M1 全链路）

### MT-04-01 【P0】UX-D 向导创建 JSON→XML 模板并预览

- **步骤**：`转换配置 → 报文转换` → 点"新建"进入向导 → 逐步：
  1. 步骤 1（背景说明）：填模板名 `MT_TPL_JSON2XML`
  2. 步骤 2（选源格式）：选 JSON，选 XML 目标
  3. 步骤 3（源报文示例）：粘贴 `{"user":{"name":"张三","age":30}}`
  4. 步骤 4（字段映射）：拖拽 `user.name → user/name`，`user.age → user/age`
  5. 步骤 5（字段加工，可选）：跳过
  6. 步骤 6（预览）：点"预览"
  7. 步骤 7（保存）：确认
- **预期**：
  - 每步"下一步"可用，"上一步"回退不丢数据
  - 预览显示 `<user><name>张三</name><age>30</age></user>`
  - 保存成功提示，跳回模板列表
- **DB 校验**：`SELECT id, name, src_format, target_format, is_latest FROM convert_template WHERE name='MT_TPL_JSON2XML';` 应有 1 条 `is_latest=1`

### MT-04-02 【P1】按钮悬浮提示（FB-027 回归 · UX-D）

- **步骤**：在向导选源/目标格式步骤，鼠标悬停在 `JSON / XML / CSV / FORM` 按钮
- **预期**：出现 tooltip 说明每种格式的含义（不再是光秃秃的按钮）

### MT-04-03 【P1】字段加工三规则叠加

- **步骤**：编辑 MT-04-01 创建的模板 → 加工步骤 → 对 `user/name` 加：`TRIM(BOTH)` → `TO_UPPER` → `SUBSTRING(0,5)` → 预览
- **预期**：`张三` 长度不够 5 时保持原文；改测试值为 `"  hello world  "` 预览得 `HELLO`
- **DB 校验**：`SELECT process_rules FROM convert_template WHERE name='MT_TPL_JSON2XML';` JSON 含三条规则

### MT-04-04 【P1】调用 /api/convert 全链路

- **前置**：MT-04-01 模板已存
- **步骤**：Swagger 或 Postman 调 `POST http://localhost:8080/api/convert`（带 satoken cookie）：
  ```json
  {
    "templateId": <上一步ID>,
    "message": "{\"user\":{\"name\":\"李四\",\"age\":25}}"
  }
  ```
- **预期**：响应 `code=200`，`data` 含 XML 字符串
- **DB 校验**：`SELECT * FROM sys_log WHERE module='报文转换' ORDER BY id DESC LIMIT 1;` 有本次操作日志

### MT-04-05 【P1】渠道模板路由自动匹配

- **步骤**：
  1. `转换配置 → 渠道模板` → 新建 `CH_TEST`，识别字段 `channelCode`，值 `APP`，关联 MT-04-01 的模板
  2. 用 Swagger 调 `/api/convert`，不传 `templateId`，body：`{"channelCode":"APP","user":{"name":"王五"}}`
- **预期**：系统按 `channelCode=APP` 自动选中模板并转换成功
- **DB 校验**：`SELECT * FROM channel_config WHERE channel_code='CH_TEST';` 应存在

### MT-04-06 【P1】模板版本管理（is_latest）

- **步骤**：对 MT-04-01 模板执行"编辑并保存" → 观察 DB
- **预期**：新增一行 `is_latest=1`，旧行 `is_latest=0`；列表页仍只显示最新版
- **DB 校验**：
  ```sql
  SELECT id, name, is_latest, create_time FROM convert_template
  WHERE name='MT_TPL_JSON2XML' ORDER BY id DESC;
  ```

### MT-04-07 【P2】非法 JSON 校验

- **步骤**：向导第 3 步粘贴 `{"user":` (缺闭合) → 点下一步/预览
- **预期**：前端提示格式非法，且指示错误位置

### MT-04-08 【P2】模板复制

## 五、端口分发（M1-7）
