## 版本命名约定

采用 [语义化版本](https://semver.org/lang/zh-CN/)：

- `vMAJOR.MINOR.PATCH`
- **MAJOR**：不兼容的 API/配置变更（v1.0 之前允许 v0.x 破坏性变更）
- **MINOR**：新功能 / 新单元交付
- **PATCH**：Bug 修复 / 视觉修正 / 文档修正

**跳包规约（2026-08-02 用户 Q2 拍板）**：

- **v1.0 前**：`MINOR` 允许跳号（如 v0.2.5 → v0.2.7 → v0.3.0 → v0.3.1 → v0.3.2 → v0.3.7)· **不需对外说明** · 主要关注功能迭代节奏
- **v1.0 及以后**：跳包必须在发版说明中标注"跳过 vX.Y.Z 原因" · 因面向对外客户交付,需清晰交代版本序列
- 此规约**不属"新增流程"**(Q16=A 用户明确"无必要勿增流程" · 本条仅是版本管理规则说明,不改会话/CR/skill 行为)

**打 tag 命令**：

```bash
git tag -a v0.1.1 -m "PowerGateway v0.1.1 · <一句话总结>"
git push origin v0.1.1
```

**打 tag 前 checklist**（**分档，用户 2026-07-26 Q9 拍板 · B 方案**）：

| Tag 类型 | 手工测试要求 | 自动化测试要求 |
|---------|---------|---------|
