#### CR-007 功能号路由 (FunctionId Routing)

- **提出日期**：2026-07-28
- **提出人**：用户
- **反馈来源**：[FB-058](./反馈簿.md#fb-058-功能号路由请求字段带则路由到内部接口--不带则-api-直调--excel-输出补功能号列--tcp-xml-必自-route)
- **需求描述**：给 PG 增加"功能号路由分发"能力。渠道方不必知道内部 `/api/exec/{id}` URL,只需按约定字段(如 `functionId`)提交,PG 根据字段值路由到对应内部接口。**规则**:
  1. 请求带 `functionId` 字段 → PG 查表找到对应 interfaceId → 转发到内部 exec 通道
  2. 请求不带 `functionId` → 走原有 `/api/exec/{id}` 直调
  3. 接口清单 xlsx (FN-09 + FN-11) 概览 sheet 加"功能号"列展示
  4. **TCP/XML 通道天然依赖路由**(报文里没有 URL 概念,必自 route)· 与 [CR-005 SOCK-5-C](#cr-005-socket--xml-报文接入闭环) 入站 Socket 编排合并做
- **动机**:
  - 金融渠道行业惯例"只知功能号不知 API 路径" · 现状 PG 只能 URL 直调,不满足对接方式
  - TCP XML 场景无 URL 概念,需路由能力才能开工(否则 SOCK-5 只能"一 Socket 端口一接口",不实用)
  - 用户明确"要改的点很多,除了刚刚说的加工路由的逻辑,还有生成 Excel 表格时这个字段要展示" —— 是**全局能力**,不是 SOCK 独有

  - **新增** `POST /api/route` 入口路由控制器(读 functionId → dispatch → 复用 ExecController 逻辑)
  - **改造** `InterfaceWizard.vue`:接口配置期指定 functionId(可选)
  - **改造** `InterfaceList.vue`:列表显示 functionId 列
  - **改造** `FN-09 InterfaceDocumentService` 概览 sheet 加"功能号"列
  - **改造** `FN-11 ConfigExportService` 概览 sheet 加"功能号"列
  - **联动 CR-005 SOCK-5-C**:入站 TCP 编排里 FunctionId 提取 → 走 `/api/route` 而不是硬编码接口 id · 共享同一套 function_id 映射表
- **预估工时**:**M-L**(4-5 人日 · 含双层机制)
- **归入版本**：**v0.3.1**（2026-08-02 用户 Q13=A 拍板 · 从 v0.3.2 前置到 v0.3.1 中间收官版 · SOCK-5-C 只复用不重造 · v0.3.2 周期回落 3.5 周）
- **状态**：✅ 已接受 · 待 v0.3.1 排期编码
- **用户 2026-08-02 关键补充**（Q1 回复里）:担心渠道方自己的 functionId 冲突 → **双层机制**:
  - **层 1**：`interface_config.function_id` 存 **我方 PG 内部功能号**(建议加 `PG-` 前缀区分 · 如 `PG-181345`)

  - **透传要求**:渠道原始 functionId 完整保留 · 转发到联机时塞入 `_originalFunctionId` 字段让联机业务处理(用户明确"实际场景就是渠道用 FunctionId 发到 lcpt-bank,PG 一并转发到联机")
