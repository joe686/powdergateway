## 一、总览：能力矩阵

按 8 个维度盘点 PG 当前能力（✅ 完全支持 · ⚠️ 部分支持 · ❌ 完全缺失），并对应到路线图版本。

| # | 维度 | 当前成熟度 | 关键 GAP | 缺口对应版本 | 阻塞真实可发布？ |
|---|------|-----------|---------|------------|-----------------|
| 1 | **协议接入层**（入/出站） | ⚠️ 仅 HTTP | Socket 入/出、MQ、gRPC、SOAP 全缺 | v0.3.0 · v0.3.2（Socket）· 其他未规划 | 🔴 **是**（银行场景必需） |
| 2 | **报文格式与编解码** | ⚠️ JSON/XML/CSV/FormData 全,分帧编解码器缺 | 定长头、XML 自闭合分帧无 | v0.3.0 SOCK-1 | 🔴 **是**（伴随 Socket） |
| 3 | **服务发现与注册**（REG-1） | ⚠️ discover 已有,self-register 占位 | PG 自注册未实装,消费方 `service://` 未联调 | v0.3.0 SOCK-1 内补齐 | 🟡 银行侧演示需要 |
| 4 | **数据源与业务库** | ⚠️ MySQL/H2 跑通,Oracle/OceanBase 未验 | Dialect 差异化框架无、SQLite 未打通 | v0.3.7（驱动预置）· v0.4.0（SQL 兼容） | 🟡 非首批客户可暂缓 |
| 5 | **权限与认证**（SYS-3） | ⚠️ Sa-Token + JWT + 三固定角色白名单 | 自定义角色、菜单分级、分级授权全缺 | v0.5.0 FN-BIZ 伴生升级 | 🟡 企业客户 SSO 需要 |
| 6 | **监控与审计**（SYS-1/2 · M2-9） | ⚠️ 三表齐全,trace_id 无跨表串 | 全链路 `trace_id` 未实装 | v0.5.0 FN-BIZ 补齐 business_op_log 时一并做 | 🟡 生产审计必需 |
| 7 | **配置管理** | ✅ CRUD/缓存/热更新/导入导出全 | 导入导出仅覆盖接口配置,报文模板/字典未含 | 后续按需 | 🟢 |
| 8 | **部署与运维** | ✅ 打包脚本齐全（**agent 错报已纠正**）,便携版可用 | Docker/SQLite/版本显示未做 | v0.3.7（Docker + 版本显示） | 🟢 打包 OK,只是 SKU 未全 |

**结论**：**协议接入层（维度 1）+ 报文分帧（维度 2）是当前唯一硬阻塞**,其他维度都是"锦上添花"或"客户方需求驱动",可按订单节奏推进。

## 二、逐维度详情

### 维度 1 · 协议接入层（入/出站）

**✅ 有**：
- HTTP 接口出/入完整（Spring Boot REST + `ExecController.execute()` 免登执行）
- 端口路由（`PortRoute` 表 + HTTP 出站转发,M1-7 已交付）
- Swagger/OpenAPI 3 文档自动生成

**❌ 缺**：
- **TCP Socket 出站**（SOCK-1,银行/前置场景必需）
- **TCP Socket 入站服务端**（SOCK-5-A,替代 lcpt-bank 必需）
- MQ / gRPC / SOAP / WebService 全缺（业务范围可暂不含）
- `ExecController.dispatchByType()` L82-108 仅支持 SELECT/INSERT/UPDATE/DELETE 4 类,type 扩展点未开放

**📌 关键文件**：
- `backend/src/main/java/com/powergateway/controller/ExecController.java` L82-108
- `backend/src/main/java/com/powergateway/service/PortRouteService.java`

**规划对应**：v0.3.0 (SOCK-1~4) + v0.3.2 (SOCK-5-A/B/C)

---

### 维度 2 · 报文格式与编解码

**✅ 有**：
- JSON/XML/CSV/FormData 四格式双向互转（`FormatConverter` + Dom4j + Jackson + OpenCSV）
- XML → JSON 扁平化（`FormatConverter.flattenMap` L218-230,点号路径）
- 报文调试可视化（`MessageDebug.vue` · v0.1.0 交付）

**❌ 缺**：
- **TCP 分帧编解码器**：4 字节大端定长头、XML 自闭合边界分隔、自定义分隔符
- **字符编码可切换**：当前默认 UTF-8,GBK/GB18030 兼容未做（银行核心系统常用 GBK）
- 二进制/Protobuf/SOAP 编解码（暂不含）
- 报文调试页扁平化预览 tab 未加

**📌 关键文件**：
- `backend/src/main/java/com/powergateway/utils/FormatConverter.java`
- `frontend/src/views/tools/MessageDebug.vue`

**规划对应**：v0.3.0 SOCK-1（编解码器）+ SOCK-3（扁平化预览 tab）

### 维度 3 · 服务发现与注册（REG-1）

**✅ 有**：
- `RegistryClient` 接口抽象 + `RegistryFacade` 门面
- Nacos/Eureka 双实现类（`NacosRegistryClient` / `EurekaRegistryClient`）
- `service://` 协议解析框架
- `discover()` 方法完整（可从 Eureka 获取外部服务实例）
- 心跳调度器骨架（`RegistryHeartbeatScheduler`）

**❌ 缺**：
- **PG 自注册到 Eureka 未实装**（`EurekaRegistryClient.selfRegister` L55-60 仅日志占位）· 意味着联机系统无法通过 Eureka 发现 PG
- `RegistryConfigController` CRUD 逻辑与前端配置页占位
- 心跳失败告警未落地
- 消费方（`PortRoute` 使用 `service://` 目标地址）实际路由切换未联调

**📌 关键文件**：
- `backend/src/main/java/com/powergateway/service/registry/eureka/EurekaRegistryClient.java` L55-60
- `backend/src/main/java/com/powergateway/service/registry/RegistryFacade.java`
- `docs/02-设计/详细设计/REG-1-注册中心集成方案.md`

**规划对应**：v0.3.0 SOCK-1 内一并补齐自注册（用户 2026-07-28 承诺提供 Eureka 实例做联调）

## 四、三种发布节奏建议

### 节奏 A · 缩范围提前发 v1.0（**"MVP 试点版"**）

**目标**：**~2 个月内**（含 v0.3.0 + v0.3.2）发一个"可演示 + 可小范围试点"的 v1.0。

**v1.0 定义收缩为**：
- 覆盖 HTTP + Socket 两大协议入/出
- 目标库仅 MySQL（Oracle 客户明确告知"待 v1.1"）
- 权限仅三固定角色
- trace_id、Docker、Oracle Dialect、SYS-3 升级、FN-BIZ 全部**推迟 v1.1+**

**版本表**：v0.3.0 (Socket 出) → v0.3.2 (Socket 入) → **v1.0**（就这样发,补文档 + 5 分钟上手手册 + 便携包 + 至少一个"银行接口 demo 模板"）

**优点**：**最快能到发布**,占位金融场景刚需,建立市场印象  
**风险**：Oracle 客户接触不到,企业客户 SSO 需求接触不到 · v1.0 定义偏"试点"

### 节奏 B · 维持当前范围,顺延到 v1.0（**"完整基础版"** · 推荐）

**目标**：**~4-5 个月内**（v0.3.0 + v0.3.2 + v0.3.7 + v0.4.0 + v0.5.0）发一个"金融行业基础可用"的 v1.0。

**v1.0 定义**：路线图现有全部范围（Socket + Oracle + SYS-3 升级 + FN-BIZ 业务菜单 + Docker + 版本显示 + trace_id 全串）

**版本表**：v0.3.0 → v0.3.2 → v0.3.7 → v0.4.0 → v0.5.0 → v1.0

**优点**：**v1.0 真正达到"金融/银行行业可交付"**,首发就能拿下 Oracle 客户和企业客户  
**风险**：4-5 个月周期长,期间不能宣布"已发布"

### 节奏 C · 扩范围推迟 v1.0（**"企业增强版"**）

**目标**：**~6-8 个月内**,在节奏 B 基础上再补:MQ 接入 / SAML SSO / 多租户 / SaaS 化底座 / 移动端管理页 / GitHub Actions CI 重启

**v1.0 定义**：节奏 B + 企业级增强,面向大客户与 SaaS 化前置

**优点**：v1.0 一次到位,后续市场化压力小  
**风险**：周期最长 · 竞品可能已经先发,先占市场
