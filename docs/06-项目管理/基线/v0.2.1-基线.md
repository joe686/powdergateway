## 七、升级步骤（老库客户 v0.2.0 → v0.2.1）

**适用**：已升级到 v0.2.0 的老库客户想拉 v0.2.1。

### 场景 A · 从 v0.2.0 平顺升级

1. `git pull` 取最新代码 + `git checkout v0.2.1`
2. **若 `sys_config` 表存在 REG-1 相关 4 条乱码**（HEX 显示 `3F`），跑数据修复：
   ```bash
   mysql -u root -p powergateway_config --default-character-set=utf8mb4 \
     < backend/src/main/resources/db/migration-encoding-fix.sql
   ```
   **注意**：客户端连接必须强制 `utf8mb4`，否则原地又打回 `?`。
3. 重启后端 + 前端

### 场景 B · 从 v0.1.x 直接跳 v0.2.1

先按 [v0.2.0 § 七 升级步骤](./v0.2.0-基线.md#七升级步骤老库客户-v01x--v020) 走完 5 步，再执行场景 A 第 2 步 + 第 3 步。

### 场景 C · 从源头治理 MySQL 客户端 GBK 问题

参见 [`docs/03-开发/MySQL字符集配置指南.md`](../03-开发/MySQL字符集配置指南.md) 7 步：改 `my.ini` 加 `character-set-server=utf8mb4` + `[client]/[mysql]` 段 `default-character-set=utf8mb4` + 重启 MySQL 服务 + JDBC url 检查。**推荐所有部署环境都做此治理**，避免未来同类问题。

### 新库客户 · 无需迁移

`init.sql` 全量 DDL 已含所有表，正确 utf8mb4 连接下 INSERT 无乱码。
