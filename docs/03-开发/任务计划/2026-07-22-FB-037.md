# FB-037 未登录访问管理台应自动跳转登录页

- **反馈**：管理台登录的时候，如果未登录，最好直接跳转到登录菜单
- **分类**：Bug · P1 · v0.1.1
- **反馈簿**：[../../06-项目管理/反馈簿.md#fb-037](../../06-项目管理/反馈簿.md)

---

## 一、现状分析

`frontend/src/router/index.js:211-228` 已实现路由守卫：

```js
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()
  if (to.meta.requiresAuth !== false && !userStore.isLoggedIn) {
    next('/login')
  } else if (...) { ... }
})
```

`/login` 路由 `meta.requiresAuth = false`，其余业务路由继承根节点 `requiresAuth = true`。**逻辑上是齐备的**。

用户反馈"未登录未跳登录"，可能的根因候选：

| 候选 | 判定手段 |
|------|---------|
| A. `useUserStore.isLoggedIn` 初始态误判（如 localStorage 恢复不同步） | 打断点 / 首帧打印 |
| B. localStorage 里残留 token（登录过一次后未 logout，但服务端已失效），前端仍视为已登录，进入业务页后 401 | 清 localStorage 复现 |
| C. 401 拦截未跳登录（`request.js` 应清 token + 跳 /login） | 触发 401，看是否跳转 |
| D. 用户误理解，其实"访问 `http://localhost:5173/` 后短暂闪过 dashboard 才跳 /login"，观感差 | 首帧优化 |

## 二、TDD 任务分解

### Task 1 · 复现 + 定位根因（Red）

- 步骤：
  1. 浏览器清 localStorage
  2. 访问 `http://localhost:5173/`
  3. 观察：是否停留在 `/dashboard` 或跳到 `/login`
  4. 若 token 残留但过期：手动改 localStorage.token = 'invalid'，访问任意业务页，观察是否被踢回登录
- 影响文件：无（诊断阶段）
- 输出：确认根因属于 A/B/C/D 哪一类

### Task 2 · 补前端单测（Red）

- 新建 `frontend/tests/router.spec.js`（或找到现有路由测试文件追加）：
  - Case 1: `isLoggedIn = false` + 访问 `/dashboard` → 断言 `next('/login')`
  - Case 2: localStorage 无 token → `useUserStore.isLoggedIn === false`
  - Case 3: 401 触发后 → `userStore.token` 应被清空 + 跳转 /login
- 影响文件：`frontend/tests/router.spec.js`（新增）+ 可能补 `frontend/tests/store-user.spec.js`
- 验收：`npx vitest run` 新用例 Red 状态

### Task 3 · 修复（Green）

按 Task 1 定位的根因决定修法：

- **若为 A**：`store/user.js` 初始化时同步从 localStorage 读 token，`isLoggedIn` getter 依赖同步值
- **若为 B**：登录页挂载时若 token 存在但校验失败（GET /api/auth/menu 401），主动 `userStore.logout()`
- **若为 C**：`src/api/request.js` 401 分支补 `userStore.logout() + router.push('/login')`
- **若为 D**：路由守卫先跑再挂载 `MainLayout`（当前 vue-router 4 默认已是这个顺序，需再确认）

一次修一个根因，一 bug 一 commit。

- 影响文件（候选）：
  - `frontend/src/store/user.js`
  - `frontend/src/api/request.js`
  - `frontend/src/router/index.js`
- 验收：Task 2 新增用例转 Green + 手工复现路径通过

### Task 4 · Refactor + 回归

- `npm run build` 通过
- `npx vitest run` 全绿
- 后端 `mvn test` 全绿（应不受影响，作为回归护栏）

## 三、验收标准（用户视角）

1. 浏览器清 localStorage 后访问 `http://localhost:5173/`，**立即**（无 dashboard 闪现）落在 `/login`
2. 手动改 localStorage.token 为无效值后访问业务页，**立即**跳 `/login` 且提示"登录已失效"或类似
3. 已登录状态访问 `/login`，跳回 `/`（原有正向逻辑不退化）
