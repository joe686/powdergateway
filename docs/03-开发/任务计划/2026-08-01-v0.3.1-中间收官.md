## Architecture

### Task 1 · CR-007 双层功能号路由

**新增后端目录**:
```
com.powergateway.route/
├── FunctionIdRoute.java              # DTO · pgFunctionId + interfaceId + channelPrefix
├── FunctionIdRouteService.java       # 路由服务:字典 fallback lookup
├── RouteController.java              # POST /api/route
└── ChannelFunctionIdMapper.java      # 渠道 functionId → PG 功能号(走 FN-12 字典)
```

**数据模型(Q19=C · 先复用 interface_config)**:
```sql
-- db/migration-v0.3.1-function-id.sql (幂等)
ALTER TABLE interface_config
  ADD COLUMN function_id VARCHAR(64) NULL COMMENT 'PG 内部功能号(建议 PG- 前缀 · 与渠道 functionId 区分)';
CREATE UNIQUE INDEX uk_interface_function_id ON interface_config(function_id);
```

**双层路由逻辑**(RouteController):
```
POST /api/route
Body: {"functionId": "181345", ...业务字段}

Step 1 · 提渠道 functionId(字段名 sys_config 可配,默认 "functionId")
Step 2 · 走 FN-12 字典 scope=3 · systemCode="ROUTE" · dictKey="channel_to_pg" · sourceValue={channelFunctionId}
        → 得 pgFunctionId(如 "PG-181345"),命中即用
        → 未命中 fallback:pgFunctionId = "PG-" + channelFunctionId(约定前缀)
        → 或直接用 channelFunctionId 走 lookup(兼容渠道直接送 PG 功能号)
Step 3 · FunctionIdRouteService.lookup(pgFunctionId) → interfaceId
Step 4 · 转 exec 链路(内部复用 ExecController 逻辑 · 拆出共享 dispatch 方法)
Step 5 · **渠道原始 functionId 完整透传给下游联机**(用户明确要求)· 存入请求 params 或 header
```

**渠道功能号字典配置示例**（用户可在字典管理菜单里配）:
```
scope=3 · systemCode="ROUTE" · dictKey="channel_to_pg"
  - "181345" → "PG-181345"
  - "180345" → "PG-180345"
  - "999999" → "PG-CUSTOM-A"     ← 渠道自定义前缀映射到 PG 内部功能号
```

**前端**:
- `InterfaceWizard.vue` 元数据 step 加"PG 功能号"输入(可选,填了才启用路由)· placeholder 建议 `PG-XXX`
- `InterfaceList.vue` 加"PG 功能号"列 · 支持搜索
- FN-09 InterfaceDocumentService 生成 xlsx 概览 sheet 加"PG 功能号"列
- FN-11 ConfigExportService 生成 xlsx 概览 sheet 加"PG 功能号"列
